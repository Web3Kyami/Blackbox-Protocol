SECURITY & PRIVACY

Hide the operator.
Keep the rule visible.

BlackBox does not hide a public protocol action. It protects who holds and exercises a bounded permission, subject to STRK20 and relay assumptions.

What stays public

  • The capability policy: target, selector, limits, and expiry
  • The target calldata, timing, and target-side state change
  • The deposit address, token, and amount
  • The capability class used in an execution

What BlackBox aims to protect

  • The wallet receiving a private pass
  • The link between issuance and later use
  • The holder as transaction sender when the wallet uses a relay path
  • Ownership of a returned reusable-pass note
01

Contract-enforced boundaries

Only the configured pool can invoke the Gatekeeper. Only the issuer can manage its policy. The target, selector, cap, expiry, and one-shot/reusable mode are verified by Cairo.

02

Current-transaction delivery

A pass must arrive from the configured pool in the same transaction that calls the Gatekeeper. A preloaded pass cannot authorize a later action.

03

Honest deployment status

Local Cairo and STRK20 E2E paths are verified. The live mainnet pool identity is read-verified. A deployed BlackBox policy and extension-wallet execution remain UNVERIFIED until owner-approved mainnet use.

Read the full model

The complete threat model, limitations, and verification status live in the protocol specification. Do not treat a private pass as a human identity credential or a guarantee against browser, wallet, RPC, or timing metadata.
